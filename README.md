# AI Game Bot for River and Stones

This repository contains an AI game bot for River and Stones, along with a playable local and web-based game environment. The project supports local games, hosted bot matches, C++ search through Python bindings, baseline opponents, and optional data collection for value-function experiments.

River and Stones is a two-player strategy game played by `circle` and `square`. Pieces can be stones or rivers. Stones race toward designated scoring cells, while rivers create flow paths that let stones travel farther than one adjacent cell. A turn can move, push, flip a stone into a river, flip a river back into a stone, or rotate a river. The engine enforces legal moves, scoring areas, timers, and board-size variants.

The full game specification is included in `A5.pdf`. This README focuses on how the bot and runtime are structured, how to build the C++ agent, and how to run matches locally or through the web server.

## What Is In The Project

The main project is organized around a Python game engine with a high-performance C++ strategy module:

- `client_server/gameEngine.py` contains the core rules, board state, legal move validation, scoring, timers, and local GUI/CLI modes.
- `client_server/web_server.py` hosts a Flask/Socket.IO match server so browser spectators and bot clients can connect to the same game.
- `client_server/bot_client.py` connects a bot to the server, pulls game state, asks an agent for a move, and submits the move back.
- `client_server/agent.py` provides Python baseline agents and the agent factory used by the engine and bot client.
- `A5.pdf` is the full game specification and rules reference.
- `student_agent.cpp` is the primary competitive agent. It is compiled with pybind11 into `student_agent_module`.
- `student_agent_cpp.py` is the Python bridge. It loads the compiled C++ module from `build/`, normalizes Python engine board objects into C++-friendly dictionaries, and exposes the `StudentAgent` API expected by the engine.
- `greedy_river_agent.cpp` and `greedy_river_agent.py` provide a stronger-than-random river-focused baseline opponent.
- `scripts/arena.py` runs batches of matches across board sizes and opponents.
- `ml/train_value.py` trains a lightweight value model from logged features.
- `models/` is reserved for optional trained value weights.
- `logs/` is reserved for generated match and training data.

Several files and directories are kept only as references or archives:

- `student_agent_old.cpp` and `student_agent_legacy.cpp` are older versions of the C++ agent.
- `duplicate_folder/` is a duplicate/snapshot copy useful for mirror matches or comparisons.
- `A2-grading-material/` is archived reference material and is not part of the runtime path.

## Architecture

The runtime path is:

1. The engine or bot client requests a move from an agent object.
2. `client_server/agent.py` resolves the requested strategy, for example `student_cpp`, `random`, `greedy_river`, or another built-in baseline strategy.
3. For `student_cpp`, Python imports `student_agent_cpp.py`.
4. `student_agent_cpp.py` prefers the compiled pybind11 module in `build/student_agent_module...so`.
5. The bridge converts the current board into plain Python dictionaries and calls `StudentAgent::choose()` in C++.
6. The C++ agent generates legal moves, searches/evaluates the position, returns a move struct, and the bridge converts that struct back into the engine's move dictionary format.
7. The engine validates and applies the move, updates timers and scoring, then advances the turn.

The C++ agent combines several techniques:

- Full legal move generation for moves, pushes, flips, rotations, and river-flow destinations.
- Alpha-beta style search with iterative/time-aware behavior.
- Transposition-table lookup and storage.
- Move ordering using hash moves, killer moves, history heuristics, tactical scoring, and immediate scoring checks.
- Repetition and no-progress tracking to avoid cycles and force progress.
- Board-size-aware scoring rows and dynamic scoring columns.
- Heuristic evaluation for scoring progress, distance to score, threats, mobility, river synergy, opening lane development, and defensive structure.
- Optional value-model support through weights generated by the ML tooling.

The Python layer stays intentionally thin around the C++ agent. Python owns orchestration, web communication, engine integration, logging, and fallback behavior; C++ owns expensive search and evaluation.

## Requirements

Use Python 3.9 or newer. A C++17 compiler, CMake, and pybind11 are required to build the main C++ agent.

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r client_server/requirements.txt
pip install pybind11
```

On macOS, `clang++` from Xcode command line tools is sufficient. On Linux, install `g++` and `cmake` through your package manager if they are missing.

## Build

Build the main C++ agent:

```sh
make cmake-rebuild
```

This creates the pybind11 extension in `build/`. The generated build directory is ignored by git.

Build the greedy river baseline:

```sh
make greedy-build
```

## Run Locally

Run a no-GUI AI-vs-AI game with the C++ student agent:

```sh
make run-aivai
```

Useful variants:

```sh
make run-aivai-gui
make run-hvai
make run-hvai-gui
make run MODE=aivai CIRCLE=random SQUARE=student_cpp BOARD_SIZE=medium TIME_MIN=1.0
```

You can also call the engine directly:

```sh
PYTHONPATH=. python3 client_server/gameEngine.py --mode aivai --circle random --square student_cpp --board-size small --time 1.0 --nogui
```

## Run With Web Server

Start the server:

```sh
python3 client_server/web_server.py 8080
```

Open:

```text
http://localhost:8080
```

Connect bots from separate terminals:

```sh
make cmake-rebuild
PYTHONPATH=. python3 client_server/bot_client.py circle 8080 --strategy student_cpp
PYTHONPATH=. python3 client_server/bot_client.py square 8080 --strategy greedy_river
```

For a remote server, pass `--server <host>` to the bot client.

## Batch Evaluation

Run batches of games through the arena script:

```sh
python3 scripts/arena.py --games-per-size 5 --sizes small medium large --matchups greedy random duplicate self
```

Enable value-data logging:

```sh
python3 scripts/arena.py --games-per-size 5 --sizes small medium large --matchups greedy random self --log
```

Generated logs are written under `logs/` and are ignored by git.

## Value Model Experiments

The optional ML flow trains a small ridge-regression value model over the 16-dimensional state feature vector used by the C++ agent.

```sh
python3 ml/train_value.py --input logs/value_data.jsonl --out models/value_v1.txt --l2 1e-3
```

`models/value_v1.txt` is a generated artifact and is ignored by git. Keep `models/.gitkeep` so the directory exists without committing trained weights.

## Repository Hygiene

Only source code, docs, scripts, templates, and lightweight placeholders should be committed. The `.gitignore` excludes:

- Python caches and virtual environments.
- CMake/Make build outputs and compiled extensions.
- Generated logs and trained model weights.
- Local editor/OS files.
- Local duplicate/archive copies that are useful during experiments but not needed to run the project.

If a generated file is already tracked, remove it from git tracking once:

```sh
git rm --cached -r client_server/__pycache__ logs/value_data.jsonl
```

Then future runs will not re-add those artifacts.
